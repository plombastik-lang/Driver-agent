# Driver Agent v7.5

## Изменения по тестированию двух аналитиков
- Разделены этапы определения драйвера и формирования его стоимости.
- Драйвер определяется только как показатель + комбинация аналитик.
- Тип эффекта, направление, база, метод расчёта и P&L относятся к стоимости.
- Расходный эффект больше не переименовывает показатель НСИ в «Сокращение ...».
- Добавлен смысловой gate: формула самого показателя (например количество × средний чек = объём) не принимается как стоимость; агент просит продолжить логику до P&L.
- Пользователь может описывать логику свободным языком; простое правило «100 ₽ каждый месяц 36 месяцев» разбирается напрямую.
- Нулевой профиль не считается валидной стоимостью и не может быть сохранён.
- Для модели формулировка «другая логика стоимости» отделена от изменения исходных показателей.
- Дополнительные аналитики не наследуются из похожего драйвера без явного выбора пользователя.

# Driver Agent v7.1

Исправление регрессий v7.1:
- выбор конкретного продукта больше не зацикливается: пользовательский flow резолвит только core-справочник, а synthetic SCALE_PRODUCTS оставлен только для скрытого нагрузочного теста;
- точный выбор кнопки (например, «Потребительский кредит») принимается детерминированно без повторной LLM/fuzzy-проверки;
- после «Сбросить демо» модельные драйверы сразу пересчитывают стоимость и P&L, поэтому в реестре больше не появляются готовые драйверы с 0 ₽;
- добавлен инвариант: статус «Готов» не допускается при нулевой стоимости;
- диагностика LLM точнее поясняет, что тест соединения подтверждает endpoint, а не корректность каждого рабочего ответа;
- cache/service-worker версия обновлена до 7.0.

Сохранены изменения v7.1: нормализация расходных показателей и фильтрация P&L по типу эффекта.

## Что исправлено
- Профиль стоимости и P&L в карточке синхронизированы по месяцам. Добавленный месяц сразу появляется в распределении P&L, а изменение общей стоимости перераспределяет статьи с сохранением текущих долей.
- Редактирование статей P&L стало полноценным: у каждой статьи есть активный выпадающий список и кнопка удаления; можно добавлять несколько статей.
- Изменение сумм по статьям P&L пересчитывает общий эффект месяца и профиль драйвера.
- У каждого ручного месяца появилась кнопка удаления.
- Пустые месяцы нельзя сохранить — их надо заполнить или удалить.
- Нельзя сохранить или согласовать драйвер с полностью нулевой стоимостью. Нулевой месяц внутри ненулевого профиля допускается.
- Мобильная таблица P&L ужата до ширины экрана: статьи остаются столбцами, справа виден общий эффект.

## Контрольный сценарий
Открой ручной драйвер → добавь месяц → введи стоимость → убедись, что тот же месяц и сумма появились в P&L. Добавь вторую статью, выбери её из списка и отредактируй распределение. Затем удали лишний месяц.

## v7.5 — compact choice UX + multi-P&L state fix

- Исправлен multi-select P&L: после подтверждения 2+ статей агент больше не возвращается к повторному выбору; сразу спрашивает распределение стоимости между выбранными статьями.
- P&L на мобильном показан компактным вертикальным checklist вместо крупных chips.
- Одновременный подбор показателя и продукта показан компактными radio-строками.
- Сразу показываются до 3 кандидатов на сущность; остальные раскрываются через «Ещё N вариантов».
- «Продолжить» и «Отмена» собраны в компактную action-зону и больше не занимают отдельные крупные капсулы.
- Обработчик кликов использует ближайшую кнопку, поэтому тап по маркеру/тексту внутри строки корректно выбирает вариант.


## v7.9
- Исправлена интерпретация unit economics для формулировок вида «1% изменения стоит Банку 10 000 ₽»: это стоимость изменения показателя, а не ежемесячное снижение на 1%.
- В интерфейсе больше не выводится `undefined мес.`; правила стоимости формулируются обычным русским языком.
- Проверка показателя усилена: перед фиксацией драйвера выполняется поиск по справочнику и при неоднозначности показываются кандидаты.
- Карточка очищает старые некорректные подписи с `undefined`.
